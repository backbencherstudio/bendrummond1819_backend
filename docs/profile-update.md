# Profile and notification updates

Apply the new database column before starting the updated backend:

```bash
npx prisma migrate deploy
npx prisma generate
npm run start:dev
```

`PATCH /api/auth/update` requires a user Bearer token. It accepts JSON for text/settings or multipart/form-data for text/settings plus an optional `image` file. Swagger at `/api/docs` documents the multipart file picker. Let your HTTP client set the multipart Content-Type boundary.

All fields are optional. You can update only the image, only the name, only the email, or one notification switch in any request, and repeat updates whenever needed. Omitted values are unchanged. At least one field or image is required. `GET /api/auth/me` and the update response return the saved preferences and profile with `avatar_url`; passwords are never returned.

Profile fields: `name`, `email`, `phone_number`, `date_of_birth`. Optional additional fields: `country`, `state`, `city`, `address`, `zip_code`, `gender`. Phone numbers must include the international country prefix and are stored in E.164 format. Date of birth accepts `YYYY-MM-DD` or the app ISO timestamp and stores its date portion. Invalid/future dates are rejected.

Password changes use the separate `POST /api/auth/change-password` endpoint. The profile update API rejects `password` and `confirm_password`. Changed email and phone values clear the corresponding verified timestamp; use the existing verification endpoints to verify the new contact details.

Settings use the existing API spelling: `bill_remainders`, `notification_remainder`, and the new `email_updates`. Send JSON booleans or multipart `true`/`false`. False is persisted. Existing users default to email updates enabled, matching the supplied app screen.

Example settings update:

```json
{
  "bill_remainders": false,
  "notification_remainder": false,
  "email_updates": true
}
```

Example profile update:

```json
{
  "name": "John Doe",
  "email": "john@example.com",
  "phone_number": "+8801785412308",
  "date_of_birth": "1999-12-31T00:00:00.000Z"
}
```

`image` accepts JPEG, PNG and WebP up to 5 MB. File headers and declared content types are checked, and filenames are generated by the server. The old avatar is deleted only after a successful database save. A failed save cleans up the new upload.

Invalid input returns HTTP 400; conflicting email/phone returns 409; a missing user returns 404. The update only writes explicitly supported profile fields; role/type changes are rejected.
